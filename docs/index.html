Independent agents. Shared direction.

Fellows explores a peer-first runtime where independent AI agents reason, exchange findings, negotiate work and deliver together — supported by deterministic coordination rather than a permanent lead model.

01 — The problem

Parallel execution does not automatically create a team

Several model sessions can produce more activity, but without shared context and explicit coordination they can also increase duplicated work, stale information and integration cost. Fellows focuses on that systems problem.

Coordination is the missing layer

Agents need a way to share evidence, disagree constructively, establish ownership and verify the combined result. A chat transcript alone is not a reliable project state.

  • 01
    Context drifts between independent sessions
  • 02
    Tasks are duplicated or dependencies are missed
  • 03
    Disagreements are not resolved or recorded
  • 04
    Concurrent artifact changes conflict during integration
  • 05

02 — System architecture

Separate peer reasoning from deterministic control

Fellows proposes three cooperating planes. The separation keeps agents independent while giving the runtime a reliable source of truth for state, permissions and execution.

Logical system layers
01

Peer layer

Independent sessions, direct messages, proposals, challenges and reviews

02

Control plane

Shared state, event history, task ownership, policy and recovery

03

Execution plane

Scoped tools, isolated workspaces, integration and verification

Logical boundaries; not a prescribed process topology

01

Agent runtime

Independent model sessions with explicit identities, capabilities, working context and execution budgets.

02

Collaboration protocol

Typed messages, decisions, task offers, claims, reviews and attributable findings.

03

Project state

Requirements, dependencies, decisions, artifacts and an inspectable event history.

04

Runtime control plane

Validated transitions, scheduling, permissions, budgets, cancellation and recovery.

05

Execution and verification

Controlled tool access, isolated changes, integration checks and acceptance evidence.

03 — Operating model

From independent interpretation to verified delivery

The collaboration pattern should adapt to the task. Independent exploration, parallel execution, pair work and independent review are options, not mandatory steps in a fixed pipeline.

01 / Intake

Interpret

Establish the objective, constraints and acceptance criteria.

02 / Deliberation

Exchange

Share findings, challenge assumptions and record decisions.

03 / Planning

Organise

Define bounded tasks, dependencies and ownership.

04 / Execution

Build

Work in scoped environments and publish attributable artifacts.

05 / Verification

Integrate

Review changes and test against the original objective.

04 — Collaboration protocol

Messages are proposals. State changes are validated.

The protocol distinguishes communication from authority. An agent can request an action, but the control plane validates the request before it changes project state.

This keeps peer discussion open while preventing an untrusted message or model output from silently granting ownership, permissions or completion status.

01Proposal

An agent shares an approach, its rationale and expected outcome.

02Challenge

A peer contributes evidence, identifies risk or offers an alternative.

03Decision

The outcome, rationale and unresolved disagreement are recorded.

04Task claim

The runtime checks availability and policy before assigning ownership.

05 — Evaluation

More agents is not a result. Evidence is.

The proposed experiment compares peer-first collaboration with simpler alternatives. The goal is to measure whether the extra coordination produces a better result or a better quality-to-cost trade-off.

A / Baseline

Single agent

One model session receives the task and produces the result. This establishes the simplest reference point.

One model session
B / Baseline

Orchestrated team

A primary agent decomposes the work and delegates to other sessions under a conventional hierarchy.

Supervisor and delegates
C / Fellows

Peer-first team

Independent agents exchange information and coordinate through shared project state without a permanent supervisory model.
