Why Fellows

Coordination should be part of the system, not another prompt

Running several agents in parallel does not automatically make them a team. They can duplicate work, lose context, make conflicting changes or reach incompatible conclusions. Fellows investigates the protocols and runtime infrastructure needed to make collaboration explicit and reliable.

The design separates peer reasoning from the deterministic control plane that owns project state, task claims, permissions, budgets and recovery. The aim is to keep agents independent without making the system itself unpredictable.
