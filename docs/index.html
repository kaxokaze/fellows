Independent agents. Shared direction.

Peer-first collaboration for autonomous AI agents

Explore the repository ↗ Discuss

A different way for AI agents to work together: independent reasoning, shared project state and coordination without a permanent lead model.

Fellows explores how autonomous agents can exchange evidence, negotiate work, resolve conflicts and deliver verified results as peers. A deterministic control plane keeps project state, permissions and execution accountable.

●
Research-stage project. The repository currently contains specifications and planning documents. There is no runnable runtime, SDK, CLI or benchmark implementation yet.

1. The coordination problem

Parallel execution does not automatically create a team. Without shared context and explicit coordination, several model sessions can increase duplicated work, stale information and integration cost.

The missing layer: agents need to exchange evidence, challenge assumptions, establish ownership and verify the combined result. A chat transcript is not a reliable project state.
  • Context drifts between independent sessions.
  • Tasks are duplicated and dependencies are missed.
  • Disagreements are not resolved or recorded.
  • Concurrent changes conflict during integration.

2. A flexible operating model

The collaboration pattern should adapt to the task. Exploration, parallel execution, pair work and independent review are options—not mandatory stages in a fixed pipeline.

01 / INTAKEInterpretSet the objective and acceptance criteria.
02 / PEERSExchangeShare findings and challenge assumptions.
03 / PLANOrganiseDefine work, dependencies and ownership.
04 / BUILDExecuteWork in scoped environments.
05 / VERIFYIntegrateReview against the original objective.

3. System architecture

Fellows separates peer reasoning from deterministic coordination. Three logical planes keep participants independent while providing a reliable source of truth for state, policy and execution.

01 · Peer layer
Independent reasoningModel sessions, direct messages, proposals, challenges, findings and reviews.
02 · Control plane
Deterministic coordinationShared state, event history, task ownership, policy checks and recovery.
03 · Execution plane
Controlled workScoped tools, isolated workspaces, integration and verification.
System areaResponsibility
Agent runtimeIndependent model sessions, identities, capabilities, context and execution budgets.
Collaboration protocolTyped messages, decisions, task offers, claims, reviews and attributable findings.
Project stateRequirements, dependencies, decisions, artifacts and inspectable event history.
Control and executionValidated transitions, scheduling, permissions, cancellation, isolated changes and acceptance evidence.

See the architecture specification and coordination proposal.

4. Collaboration protocol

Messages are proposals; state changes are validated. An agent may request an action, but the control plane checks it before it changes project state or grants ownership.

MessagePurpose
ProposalShare an approach, rationale and expected outcome.
ChallengeContribute evidence, surface risk or offer an alternative.
DecisionRecord outcome, rationale and unresolved disagreement.
Task claimCheck availability and policy before ownership is assigned.

5. Evaluation before claims

More agents is not a result; evidence is. The proposed experiment compares peer-first collaboration against simpler baselines.

A / BASELINESingle agentOne model session completes the task.
B / BASELINEOrchestrated teamA primary agent delegates to other sessions.
C / FELLOWSPeer-first teamIndependent agents coordinate through shared state.

Measures: outcome quality, latency and compute cost, duplicated work and conflicts, and human interventions. The first experiment is exploratory; it should not support broad performance claims.
