AI agents should be able to work as peers.

Fellows is exploring a peer-first runtime for independent AI agents: shared project state, direct communication, negotiated work, and coordinated execution—without a permanent lead model directing every decision.

01 / Problem space

Parallel agents are not yet a team.

Running multiple model sessions can increase throughput, but it also creates coordination problems: duplicated work, stale context, conflicting edits, unresolved decisions, and integration overhead. Fellows focuses on the runtime mechanisms needed to manage those costs.

01 — STATE

Shared project context

Requirements, discoveries, decisions, and dependencies need a durable source of truth that every agent can inspect and update safely.

02 — PROTOCOL

Direct agent communication

Agents need typed proposals, questions, challenges, findings, task offers, and reviews—not an unstructured stream of chat alone.

03 — COORDINATION

Negotiated work ownership

Tasks need explicit dependencies, atomic claims, bounded leases, and recovery when an agent stalls or fails.

04 — EXECUTION

Conflict-aware changes

Independent work should happen in controlled environments, with artifact ownership, integration checks, and reviewable changes.

05 — CONTROL

Deterministic safety

Permissions, budgets, state transitions, cancellation, and audit history must not depend on an agent following instructions.

06 — EVALUATION

Evidence over agent count

Peer collaboration should be compared with single-agent and orchestrated baselines under comparable model and resource budgets.

02 / Operating model

One objective. A coordinated team.

The intended workflow moves from independent interpretation to shared decisions, negotiated responsibilities, controlled execution, and verification. It is a design target for the first prototype.

01 / INTAKEInterpret

Agents inspect the goal, constraints, and acceptance criteria.

02 / DELIBERATIONExchange

They share evidence, challenge assumptions, and record decisions.

03 / PLANNINGOrganize

Work is proposed, claimed, and connected by dependencies.

04 / EXECUTIONBuild

Agents work independently or together within scoped tools.

05 / VERIFICATIONIntegrate

Changes are reviewed and tested against the user’s objective.

Peer reasoning does not mean leaderless infrastructure. Fellows proposes independent agents backed by a deterministic control plane for state, scheduling, permissions, and recovery.
03 / System architecture

Separate reasoning from control.

The proposed runtime separates agent behavior from the infrastructure that maintains consistency and enforces policy. This keeps the collaboration model flexible without making critical state transitions probabilistic.

Peer layer

Independent model sessions, private working context, direct messages, proposals, challenges, task offers, and reviews.

Control plane

Project state, event persistence, task claims and leases, dependency tracking, budgets, policy checks, and cancellation.

Execution plane

Scoped tools, isolated workspaces, artifact changes, command limits, and auditable external operations.

Provider adapters

Model-specific APIs behind a common interface for capabilities, tool calling, limits, usage, and cancellation.

04 / Development status

Design first. Validate with a small prototype.

The repository currently contains design documents and a proposed evaluation method. The implementation has not started. The first experiment is intentionally limited to three agents and one bounded software task.

05 / Research and contribution

Help pressure-test the design.

The most useful contributions at this stage are architecture review, relevant research, protocol critique, failure-mode analysis, and suggestions for reproducible evaluation tasks. We are particularly interested in where peer collaboration breaks down and where a simpler orchestrated design is likely to work better.
