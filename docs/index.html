01 / The problem

Parallel work is easy to start. Reliable collaboration is harder.

Adding more model sessions can create more output, but it can also create more coordination work. Fellows focuses on the systems required to make independent agents useful to one another.

What breaks in practice

More agents can mean more overhead

  • Context drifts between separate sessions
  • Work gets duplicated or dependencies go unnoticed
  • Disagreements remain unresolved or unrecorded
  • Concurrent edits collide during integration
  • Completion is reported without verifiable evidence
The Fellows thesis

Keep reasoning independent. Make coordination explicit.

Agents should be able to exchange proposals, questions, findings and reviews directly. A deterministic runtime should own durable state, task transitions, permissions, budgets and recovery — without becoming a permanent lead model.

02 / System architecture

Three planes. One coherent system.

The design separates the work agents do from the infrastructure that keeps their collaboration consistent, bounded and auditable.

Peer reasoning

Tools and workspaces stay within explicit boundaries. Changes remain attributable and pass through integration and verification.

03 / Collaboration protocol

Conversation should change the shared work.

The protocol proposal treats messages as attributed events and requests — not as commands that can silently mutate authoritative project state.

01 PROPOSAL

Put forward an approach

An agent shares a plan, rationale and expected outcome.

02 CHALLENGE

Test the assumptions

A peer raises evidence, risk or a different interpretation.

03 DECISION

Record the outcome

The result and its rationale become part of project history.

04 TASK CLAIM

Take bounded ownership

The runtime validates the claim before work is assigned.

Messages are proposals and information Validated transitions belong to the control plane

04 / Operating model

From independent interpretation to verified delivery.

The intended flow adapts to the work. Not every task needs a long debate or maximum parallelism; collaboration should be proportional to uncertainty, dependencies and risk.

01 / INTAKE

Interpret

Understand the goal, constraints and acceptance criteria.

02 / DELIBERATE

Exchange

Share findings, test assumptions and record decisions.

03 / PLAN

Organise

Define bounded tasks, dependencies and ownership.

04 / EXECUTE

Build

Work in scoped environments and publish attributable artifacts.

05 / VERIFY

Integrate

Review changes and test against the original objective.

05 / Evaluation

More agents is not a result. Evidence is.

The project proposes a controlled comparison to find out whether peer-first collaboration improves task quality or the quality-to-cost trade-off enough to justify its coordination overhead.
