Fellows

Peer-first collaboration for autonomous AI agents
Repository Issues

Fellows explores a peer-first runtime where independent AI agents reason, exchange findings, negotiate work and deliver together — supported by deterministic coordination rather than a permanent lead model.

The project investigates the systems work behind useful collaboration: shared project state, agent-to-agent communication, task negotiation, conflict-aware execution and verifiable integration.

1. Problem statement

Parallel execution does not automatically create a team. Several model sessions can produce more activity, but without shared context and explicit coordination they can also increase duplicated work, stale information and integration cost.

The coordination problem
Agents need a way to share evidence, disagree constructively, establish ownership and verify the combined result. A chat transcript alone is not a reliable project state.
  • Context drifts between independent sessions.
  • Tasks are duplicated or dependencies are missed.
  • Disagreements are not resolved or recorded.
  • Concurrent artifact changes conflict during integration.
  • Completion is reported without sufficient evidence.

2. Architecture

Fellows proposes three cooperating planes. The separation keeps agents independent while giving the runtime a reliable source of truth for state, permissions and execution.

01 · Peer layer
Independent reasoningIndependent sessions, direct messages, proposals, challenges and reviews.
02 · Control plane
Deterministic coordinationShared state, event history, task ownership, policy enforcement and recovery.
03 · Execution plane
Controlled workScoped tools, isolated workspaces, integration and verification.

These are logical boundaries, not a prescribed process topology.

Principal system areas

AreaResponsibility
Agent runtimeIndependent model sessions with explicit identities, capabilities, working context and execution budgets.
Collaboration protocolTyped messages, decisions, task offers, claims, reviews and attributable findings.
Project stateRequirements, dependencies, decisions, artifacts and an inspectable event history.
Runtime control planeValidated transitions, scheduling, permissions, budgets, cancellation and recovery.
Execution and verificationControlled tool access, isolated changes, integration checks and acceptance evidence.

3. Operating model

The collaboration pattern should adapt to the task. Independent exploration, parallel execution, pair work and independent review are options, not mandatory steps in a fixed pipeline.

  1. InterpretEstablish the objective, constraints and acceptance criteria.
  2. ExchangeShare findings, challenge assumptions and record decisions.
  3. OrganiseDefine bounded tasks, dependencies and ownership.
  4. BuildWork in scoped environments and publish attributable artifacts.
  5. IntegrateReview changes and test against the original objective.

4. Collaboration protocol

Messages are proposals; state changes are validated. An agent can request an action, but the control plane validates the request before it changes project state. This keeps peer discussion open while preventing an untrusted message or model output from silently granting ownership, permissions or completion status.

Message typePurpose
ProposalAn agent shares an approach, its rationale and expected outcome.
ChallengeA peer contributes evidence, identifies risk or offers an alternative.
DecisionThe outcome, rationale and unresolved disagreement are recorded.
Task claimThe runtime checks availability and policy before assigning ownership.

Related documents: coordination protocol and peer-first architecture decision record.

5. Evaluation

More agents is not a result; evidence is. The proposed experiment compares peer-first collaboration with simpler alternatives to determine whether extra coordination produces a better result or a better quality-to-cost trade-off.

A / BASELINE

Single agent

One model session receives the task and produces the result. This establishes the simplest reference point.

B / BASELINE

Orchestrated team

A primary agent decomposes the work and delegates to other sessions under a conventional hierarchy.

C / FELLOWS

Peer-first team

Independent agents exchange information and coordinate through shared project state without a permanent supervisory model.

Proposed measurement dimensions

  • Outcome quality: acceptance tests and review findings.
  • Efficiency: latency, tokens and compute cost.
  • Coordination: duplicate work, conflicts and retries.
  • Human effort: interventions and blocker resolution.
The first experiment is exploratory. It should not be used to make broad performance claims. See the evaluation plan.
