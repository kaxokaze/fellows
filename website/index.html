FELLOWS / INDEPENDENT AGENT COLLABORATION

Independent agents.
Shared direction.

A peer-first approach to AI collaboration—where agents communicate as equals and a deterministic control plane keeps shared work coherent.

The research question: can independent agents coordinate, challenge, and integrate work more effectively without relying on one model as the permanent supervisor?

01 / THE PROBLEM

Parallel agents do not automatically make a team.

Multiple model sessions can work at once, but parallel execution creates its own coordination problems. Context drifts, tasks overlap, decisions disappear, and individually plausible changes can fail when combined.

01 / CONTEXT

Shared understanding

Agents need a consistent view of the objective, current state, dependencies, and decisions—not just a copied prompt.

02 / OWNERSHIP

Coordinated work

Work must be divided without duplicate effort, conflicting claims, or hidden blockers.

03 / TRUST

Verifiable outcomes

Changes need provenance, permission boundaries, integration rules, and evidence that the result meets the request.

02 / DESIGN MODEL

Peers for reasoning. Rules for shared state.

Fellows separates the freedom to reason from the authority to change project state. Agents can disagree and exchange ideas directly; the control plane validates the actions that affect the project.

LAYER A

Peer reasoning

Independent sessions share findings, propose approaches, ask questions, challenge assumptions, negotiate tasks, and review artifacts.

LAYER B

Deterministic coordination

A control plane validates messages and state transitions, manages task ownership, applies permissions, records events, and coordinates integration.

Agent sessions

Separate model contexts with declared capabilities, responsibilities, and provider configuration.

Collaboration protocol

Typed, attributable messages for proposals, findings, task claims, decisions, and reviews.

Shared project state

A durable record of goals, requirements, tasks, dependencies, decisions, artifacts, and events.

Control and execution

Explicit authorization, bounded actions, attributable changes, integration, and verification.

03 / COLLABORATION FLOW

A proposed lifecycle, not a fixed agent script.

The system should adapt the amount of collaboration to the task. A short request should not trigger unnecessary debate; a risky change should not skip review and verification.

Understand

Establish the goal, constraints, deliverables, and acceptance criteria.

Exchange

Agents interpret the task independently and share evidence, proposals, and objections.

Decide

Record outcomes and unresolved risks under an explicit decision policy.

Negotiate

Offer work, validate task claims, and make dependencies visible.

Execute

Perform approved work through scoped capabilities and attributable changes.

Verify

Integrate, test against acceptance criteria, and report evidence and limitations.

04 / FIRST EXPERIMENT

Prove the coordination model before expanding it.

The initial experiment is one bounded software task completed under three conditions: a single agent, a conventional orchestrated team, and Fellows. Model versions, prompts, permissions, and spending limits should be comparable.

BASELINE A

Single agent

One model session receives the task and produces the result.

BASELINE B

Orchestrated team

A primary agent plans and delegates work to other sessions.

TEST C

Fellows

Independent agents communicate directly through shared project state and deterministic coordination.

Result quality: acceptance tests, requirement coverage, review findings.
Model cost: input/output tokens and provider-reported API spend.
Efficiency: completion time and cost per accepted result.
Coordination: duplicated work, conflicts, rework, and human interventions.

A positive result is not assumed. If peer collaboration does not justify its added cost and complexity, the design should change.

06 / FUNDING

Support the first implementation.

Fellows is currently looking for two forms of support. Requests are limited to model access and funding that directly helps move the research into an initial implementation.

REQUEST 01

AI model and API credits

Capped inference credits or research API quotas to build independent agent sessions and run controlled comparisons across model providers.

REQUEST 02

Financial funding

Open-source grants, one-time contributions, recurring sponsorships, and suitable investment discussions, including potential equity arrangements.

Financial support would fund maintainer time, the initial runtime, API usage, and controlled evaluation. Bank-transfer details are available on request. No GPU, compute, hosting, infrastructure, developer-tool, or mentorship support is being requested.
